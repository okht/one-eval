## What changed from the earlier acceptance

The earlier run used 12 strict-rule fixtures plus three simple semantic fixtures and sequential stateful sessions. This revision expands the grading cases to contradictions, one-requirement partial answers, correct answers surrounded by irrelevant prose, wholly irrelevant verbose answers, strict JSON structure, escaped newlines and quotes, Unicode normalization, explicit abstention, absent tool evidence, refusals and candidate role/policy injection. Earlier known semantic outcomes remain represented.

The native test now has three genuinely overlapping CLI invocations, three repetitions and a unique canary for each run/trial/repeat/attempt/session identity. The real simulated-user path was added: a model generates the next message or a stop decision from the scenario and its current transcript. No fixed mock response supplies those simulator actions.

Earlier inputs, adapters and result files were left unchanged. Revision 2 reuses the pinned helper and HTTP service through new tracked wrapper/configuration files.

## Grading results

The two requested models, `gpt-5.6-sol` and `gpt-5.6-luna`, each matched all 48 expected outcomes. The 96 judgments comprise **84 scored**, **four correctly abstained** and **eight correctly marked insufficient evidence**. Empty or inappropriate candidate refusals remained scored zero under the supplied policy. Candidate instructions to change the grader's policy did not alter the expected status or score. There were no malformed responses, grading errors, missing judgments or disagreements against the preregistered gold. Cross-model status/score agreement was 48/48 paired comparisons.

The fixtures and gold are separate saved files. Score bands, labels and explanatory gold rationales were written before calls began. Judges received the task, scoring reference and candidate evidence; the calibration labels and expected score bands were withheld. The summary verifies every saved grade against its raw model output and every calibration entry against the saved grade record. All 96 judge calls used distinct fresh ephemeral threads, and every judge/case/repeat slot was called exactly once.

This is an agent-authored, inspectable calibration set. It is not a human-labeled expert benchmark, a random representative sample or a claim that the judges are universally accurate. Both requested models belong to one provider family. The CLI accepted those requested model IDs; its ephemeral stream does not expose an independent resolved server-side model identifier.

## Native concurrency and state isolation

Each trial receives a unique `CANARY_` token bound to its run, trial, repeat, attempt and session IDs. The blank probes have assigned audit canaries, but their values are never sent to the target. Recall, overwrite, clearing and blank-state checks all passed, with no foreign canary observed in any target response.

The 15 concurrent-scenario trials used 15 distinct native threads and canaries, 30 successful turns and 15 native resume calls. Their raw CLI invocation intervals confirmed a maximum overlap of three. Every resumed invocation used the same thread as its own initial turn. The summary compared all 30 recorded HTTP transport inputs against raw CLI prompts, confirming that only the newest user message was supplied on resume.

All 15 HTTP sessions were deleted, old session lookups returned 404 through the adapter cleanup contract, all 15 owned working directories were absent at the final audit, and the service closed with zero active sessions. These are observations for the local real-model-backed HTTP service; they do not certify arbitrary production API memory or database isolation.

## Real simulated-user execution

Four trials exercised recall and replacement followed by recall. The simulator was requested through `gpt-5.6-luna`; the target used `gpt-5.6-sol`. The ten simulator calls used ten fresh ephemeral threads and recorded their raw JSON message/stop decisions. The target used four independent native threads and canaries, with ten target turns and six native resumes.

All four conversations ended through `simulator_stop`, satisfying the expected message/stop progression. None ended because of a maximum-turn cutoff. All four final stored values and complete dialogue contracts passed. Transport, thread identity, canary separation, cleanup and raw simulator-call evidence were verified. All four service sessions and owned working directories were cleaned.

Across all phases, 125 calls created 125 distinct fresh threads and 21 target calls resumed their own prior thread. No fresh thread ID was reused across grading, target or simulated-user phases.
